Each row has one primary status:

| Status | Meaning in this audit |
| --- | --- |
| implemented | The described bounded interaction or controlled pipeline has identifiable current wiring. Static evidence only; not a full REQ acceptance pass or a production claim. |
| interaction gap | A concrete mismatch between a required interaction and inspected current wiring exists. Partial implementation remains credited. |
| production input missing | The identified enabling condition is external real input, permission, official approval or model-quality evidence; do not manufacture it as a UI fix. Existing engineering behavior is recorded separately. |
| needs verification | Available evidence is incomplete, ambiguous or insufficient to disposition the full behavior. A specific next check is stated. |

A gap takes precedence over a missing production condition when both apply. Every `implemented` row still requires a fresh behavior run for acceptance. Every `needs verification` row is an explicit uncovered acceptance obligation, not an implicit pass.

### Binding Notation

- **PUB**: selected `trade_date + snapshot_id`, immutable published manifest; source/version, coverage, quality, rule version and basis accompany reads. UI adapters also read `/api/snapshots/{id}` for summary/calendar.
- **ROLE**: PUB plus materialized role data binding market/topic snapshots and rule version; evidence needs `sector_id + security_id`. `topic_id` and `sector_id` must not be guessed interchangeable.
- **LOCAL**: origin-isolated IndexedDB, stable `local_profile_id`, local revisions/commands; note snapshot/date/security provenance is preserved. It is not owner authentication or an HTTP notes service.
- **AI**: owner-only task submission with `snapshot_id + as_of + version`, explicitly selected authorized text; task/revision, verification and human review states are independent.
- **RT**: intraday source/batch identity and `available_at/as_of`, independent of PUB. The current client expects null daily snapshot/rule IDs for intraday envelopes.
- **LHB**: disclosed source rows, source/mapping versions and `date/as_of`; current client uses a specialized envelope, not a daily publication pin.
- **PIT**: owner research manifest domains/versions, config/input identity and point-in-time availability; LOCAL simulation is a separate research ledger.
