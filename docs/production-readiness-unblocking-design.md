# 五项生产外部门禁解锁设计

日期：2026-11-16。状态：用户已批准，工程接入及相关验证已完成；真实外部材料待补齐。

目标：让五项外部门禁能够依据真实、可核验、适用当前候选版本的证据解锁。
证据缺失、失效或不可信时继续关闭门禁。完成工程接入与取得真实生产证据分别登记。
本设计不把合成回归、助手生成的标签或一次许可声明升级为生产证据。

## 1. 已确认的现状

开发代码位于 `.worktrees/task27-research`。此前 Task 18 的开发验收及其
549 个源文件、52 个产物的摘要绑定保持原样。

当前阻断包含两个工程缺口：

1. `scripts/verify_reset.py` 的 `_validate_manifest` 固定给五项外部门禁输出
   `blocked`，CLI 没有外部生产证据入口。这是现有开发验收的范围边界；
   新的生产证据接入必须独立设计，不能直接删除默认拒绝逻辑。
2. `research/worker.py` 的默认 `fail_closed_research_compute` 抛出
   `ResearchInputsUnavailable`。有数据授权本身不足以运行生产研究；
   还需把真实不可变输入及已物化因子接入计算装配。

项目根目录、当前开发工作树及已登记的验收资料中未找到可解锁上述门禁的材料。

## 2. 方案选择

| 方案 | 能交付什么 | 限制 |
|---|---|---|
| A：先补工程通道，再逐项接入真实材料，推荐 | 可验证的证据接入、生产输入装配、评测与影子采集流程 | 材料未到位的门禁仍 blocked；20 个真实交易日仍需实际覆盖 |
| B：先接用户现有完整资产，再实现对应适配器 | 如果已有合法数据、批准材料和历史影子记录，可优先核验并减少等待 | 依赖用户提供资产位置、供应商契约和证据所有者 |
| C：直接把状态改为 pass，排除 | 只改变显示 | 无法证明授权、评测或运行，破坏既有拒绝边界 |

推荐 A；用户已有合格材料时，在同一架构内按 B 的顺序优先处理。
五个门禁独立输出结果，已通过的门禁不被其他缺失材料覆盖。

## 3. 信任与证据接入

新增独立生产准入报告，保留开发验收和生产准入的不同信任等级。
现有 `verify_reset.py` 与 `audit_reset_release.py` 默认行为保持拒绝缺失证据；
经独立审查的显式证据接入共享同一套生产验证逻辑。

生产证据记录至少绑定：

- schema/version、gate_id、evidence_id、真实/合成标识；
- issuer、approval_id、批准与有效时间、撤销状态；
- 候选代码、数据、规则、模型、prompt、retrieval 的适用版本；
- 授权主体、用途、目标、受众及范围；
- 本地不可变材料引用、SHA-256、生产实跑报告引用；
- 签名算法、key_id、独立签名与批准者身份。

信任策略由获授权的使用者通过外部渠道确认发行方及公钥指纹，
并限定每个发行方能证明的门禁和范围。默认发行方集合为空。
助手不得创建一个新身份并自行把它加入可信集合，也不得代签人工批准。
签名只能证明身份与内容完整性；授权是否适用仍由对应证明范围和审核记录判断。

首版签章协议采用固定 canonical UTF-8 JSON、SHA-256 和 detached
RSA-PSS/SHA-256 签名；验证通过配置好的 OpenSSL 只读进程执行。
只接受该明确算法，不执行材料内的程序或命令。缺少验证工具、可信发行方或
适配该协议的真实证明时输出 blocked；不退化为仅校验摘要。
外部发行方采用其他签章协议时，需单独批准适配器后才能接入。

材料路径必须处于明确授权的本地资产根，拒绝路径越界、符号链接/junction、
重复键、未知字段、无界大小、失效或撤销证明、版本与目标不匹配。
敏感材料留在本机受保护的外部资产目录，Windows ACL/POSIX 权限按现有约定验证；
不把凭据、完整许可原文或真实新闻正文自动复制入 Git。
用户报告保存到项目根工作区，只包含适用范围、状态、原因和安全的证据摘要。

每项结果采用：

- `blocked`：材料、授权、工具、运行或可信来源尚未具备；
- `fail`：已有材料被检出无效、被篡改、不适用或实际指标失败；
- `pass`：真实来源、内容、适用范围、运行及独立批准全部有效。

单个 gate 的 pass 不代表整体可发布。总体生产准入还必须具有可信的当前版本
自动化验收、其他适用发布门禁及发布授权。Task 18 的未提交源码摘要报告不能被
改称为正式 CI 的 EXECUTED 报告。

## 4. 真实输入与生产计算装配

供应商由用户指定；不会把公开可下载自动解释为具备研究、AI 使用和公开再分发权。
优先采用既有本机 CLI 导入及不可变发布体系，保持 MarketSnapshot 与 TopicSnapshot 分离。

统一输入继续使用当前 `MarketBatch`、`TopicBatch`、`PitAnchor`、`PitFrame`
及研究内核因子观测契约：

1. 核验供应商来源、权限、真实发布时间与首次接收时间。
2. 核验历史证券身份、上市/退市、ST、停复牌、交易日历、
   raw OHLC、成交量额、复权版本和适用题材血缘。
3. 根据批准的方法版本物化因子，绑定日期、证券、来源版本、
   market/topic 快照、publication_sequence、available_at 和规则版本。
4. 不可变存储物化输入；worker 只读取当前授权且适用锚定窗口的归档。
5. 将真实装配接入 `ResearchBacktestWorker.compute`，复用 `run_backtest`、
   现有租约、取消、预算、账本及结果固化逻辑。

缺失字段和历史状态进入明确质量记录，按冻结必需字段和声明数据范围关闭门禁；
不以当前成分回填历史、不倒填首次接收时间、不把 fixture 当生产因子。
API GET 不重算，题材导入发布继续仅通过本机 CLI，无新增 Web 管理后台。
新增持久化结构若必要，应拥有独立规格、迁移和隔离回归后才能启用。

## 5. 正式规则接入

复用现有规则注册、激活、撤回与冻结样例核验。
批准包覆盖实际候选使用的监管、角色与研究方法版本，不能只提供一个泛化“已批准”字段。

监管规则须满足现有全部条件：官方绝对 HTTPS 来源、正确适用范围与半开有效期、
author/reviewer 不同、复核先于发布、review_switch=approved、
regression_passed=true、冻结样例与引擎一致、最新追加生命周期 active。
角色与研究方法仍遵守其现有资格、证据排序和版本约束；
产品方法批准不冒充交易所规定，也不把测试阈值移入生产规则。

批准记录及来源归档经可信证据接入绑定；撤回只追加新记录，
不修改历史规则、原始计算结果、快照或人工审计。

## 6. 真实模型评测

复用 `dragon-radar-ai-eval/v2` 和现有评估器。
模型供应商、候选版本、调用预算及真实原始输出由用户提供或明确配置，
凭据只来自本机受保护配置。

候选必须同时具备：

- 至少 100 个唯一真实人工输入，development 和 frozen_test 均非空；
- dataset/model/prompt/retrieval 四版本及输入输出 SHA-256；
- 人工标注者、标注时间、attestation_id、证明人与证明时间；
- 分组及全局无重复、无泄漏，真实输出与证明血缘一致；
- development 和 frozen_test 各自原子事实支持率 ≥95%；
- 数值与白名单复算一致率 100%，安全硬失败 0；
- 由实际运行产生的报告及候选版本批准记录。

失败样本和原始模型输出保留不可变引用。任何适用四版本变化必须重新评估。
助手可以准备标注表和执行评测，不充当人工真值来源。
只有这些条件满足后，才允许解除 ai_variant 的缺少真实评测输入原因；
不会因为新增了证据文件路径就启用该腿或生成收益数字。

## 7. 公开许可

用户需提供明确许可及发布目标。核验主体、数据与内容范围、目标、受众、
用途、有效期和再分发限制与实际候选一致，且批准身份受信。
来自行情授权的内部研究权限不自动成为公开分享权限。

许可撤销、过期或目标变化会使门禁重新关闭。
默认仍不部署、不发布镜像、不 push/merge/tag、不改版本号。
本轮“修复门禁”的指令不替代公开发布许可或实际部署授权。
若产品目标仅限私人本机研究，公开门禁是否改为不适用必须另有明确范围决策，
本设计不会自动将其改成 pass 或从五项列表移除。

## 8. 真实影子运行

生产输入装配、规则及模型条件到位后，复用现有 worker 与本机 CLI 采集日终证据，
不创建常驻新容器，不发真实订单。

每日记录交易日历版本、真实源接收/可用时间、授权状态、
代码/数据/规则/模型/prompt/retrieval 版本、发布快照、执行时间、
关键质量与性能指标、错误及人工复核、原始材料摘要和 previous_entry_hash。
逐日记录追加不可变，重复日期幂等；修订保留原记录，不覆盖失败历史。

首版按批准日历验证连续至少 20 个完成的真实交易日。
同日重复、重复快照、未结束交易日、缺少真实依赖或可靠接收时间、失败日期、
日期中断及语义版本变化不能静默凑满 20 天。
影响语义的版本变化重新累计，纯证据/文档变更须有范围证明才能复用记录。

已有历史记录可以导入核验，但必须是实际当天形成的原始记录及可验证时间/血缘。
现在重新运行 20 个历史日期的回测、生成 20 行 CSV 或修改系统日期不满足影子运行。
如果没有合格历史证据，这个门禁必须等待真实交易日积累。

## 9. 实施分段与验收

| 分段 | 工程交付 | 外部前提 | 成功判定 |
|---|---|---|---|
| P0 | 可信证据接入、独立生产报告、五项逐项状态、开发/生产信任隔离 | 获授权发行方与签章验证环境 | 可核验适用证据能解锁对应项；缺失/伪造/过期/越界不能解锁 |
| P1 | 供应商契约适配、不可变因子物化、生产 worker 装配 | 用户指定合法供应商、授权和冻结真实数据 | 真实授权输入驱动实际内核；PIT、版本、权限、预算、只读/私有隔离全部通过 |
| P2 | 正式规则与真实模型评测接入、公开许可核验 | 批准包、真实人工样本、模型输出、许可及目标 | 现有规则与评测阈值全部满足，许可范围匹配 |
| P3 | 日终影子证据采集与历史真实证据核验 | 可运行真实依赖和记录所有者 | 至少 20 个真实交易日有效且可追溯，逐日失败不被覆盖 |

预计代码职责分别放在 `src/dragon_radar/production/`、
`src/dragon_radar/research/` 和本机 `scripts/`，测试按证据信任、PIT 输入、
评测报告、许可范围和影子记录拆分。现有大型验收脚本只增加薄接入，
不把全部新业务堆入 `verify_reset.py`。
每段独立规格、TDD、规格复核与质量复核，保留实际退出码、来源版本和 SHA-256。

关键负向回归包括：合成材料伪装真实、自签未受信证明、签章或原文篡改、
证据撤销/过期、签名者越权、版本与目标漂移、未知字段和越界路径、
当前状态回填历史、迟到输入、缺因子、只读包泄漏、
评测器退出 0 但报告 blocked、开发集掩盖冻结集失败、
模型自标注、同日重复、回填假影子日和日志覆盖。
现有 P95≤2.0s、零写、零跳过与默认/私有构建边界不放宽。
