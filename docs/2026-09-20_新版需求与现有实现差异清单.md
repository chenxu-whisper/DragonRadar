# 新版需求与现有实现差异清单

盘点日期：2026-09-20。本文为代码与需求静态盘点，不是发布验收结果，也不是已批准的实施计划。

> **2026-09-21 范围修订：** 用户已要求将原 P1/P2 功能全部纳入本轮交付。下文“停止开发/延期”结论由本修订覆盖：实时与分钟异动、龙虎榜、词云、题材轮动、自然语言查询、深色主题、密度、命令面板、回测、模拟组合、情绪研究分与阶段标签均为本轮新增开发；仍须满足数据许可、研究标识和不接真实交易等边界。

## 1. 结论与需求基线

**现有工程有可复用的数据和计算底座，但尚未交付新版七个功能界面的 P0 产品。应保留已有资产，调整存储和接口边界，再按页面闭环交付；不建议从零重写，也不应继续照旧 Task 7～15 顺序推进。**

- 需求以 [DragonRadar_开发需求PRD.md](DragonRadar_开发需求PRD.md) 为准，特别是 §1.3、§4、§6.3、§7、§11。
- 竞品以 [gushifupan竞品分析报告 .html](gushifupan竞品分析报告%20.html) 为交互参考。本次阅读了报告正文，未重新访问网站或独立核验截图、行情与算法。
- PRD 本次读取内容的 SHA256：`C37C93C6C1B47FC6F45E44F30602DD04DD6ECC9755790721EFF71B6771747C59`。文档内仍有多个历史版本标记，以该文件内容为准。
- 旧设计中的额外限制、固定阈值和验收门禁不自动继承。与新版兼容的实现可以保留；需要产品决定的差异单列，不直接扩展开发范围。

最重要的五项差异：

1. **主分支尚无应用代码**：功能集中在未合并的开发分支，不能以 `main` 代表已有产品。
2. **私人数据存储反转**：现有笔记/自选依赖服务端 PostgreSQL；新版要求浏览器 IndexedDB 为唯一权威源。
3. **计算与页面未接通**：六类角色和历史计算存在，但角色落库、公开读模型 API、梯队页面尚未实现。
4. **读模型发布方式不同**：已有行情快照归档；部分 GET 仍现场计算，新版要求以服务端预计算结果为主。
5. **新增业务仍缺失**：消息、监管三区域、AI 异步任务与审核系统没有对应完整实现。

### 分类口径

| 分类 | 含义 |
|---|---|
| 可复用 | 有直接相关代码；接入新版后仍需验证，不等于整项已验收 |
| 需改造 | 有实现，但存储、接口、规则、部署或体验与新版不一致 |
| 缺失 | 在检查的应用源码、路由或迁移中未找到对应交付链路；文档计划不计实现 |
| 停止开发 | 暂停旧路线或本期范围外功能；保留源码和数据，不表示立即删除 |

### 3.1 私人数据迁移是明确替换项

| 项目 | 当前实现 | 新版目标 | 处理建议 |
|---|---|---|---|
| 权威存储 | `review_notes`、`watch_entries` 等 PostgreSQL 表 | IndexedDB `notes`、`watchlist` | 替换新版本默认写入路径 |
| 浏览器访问 | `fetch('/api/owner/v1…')` | `listNotes/putNote/listWatchlist/putWatchlist` 本地 Repository | 保留 UI，替换访问层 |
| 保存成功 | 服务器事务、版本及响应 | IndexedDB 事务提交＋回读一致 | 重做 S06 判定与失败恢复 |
| 冲突 | HTTP 409、If-Match/服务端版本 | 本地 revision 事务校验＋BroadcastChannel | 复用对照/另存交互；并发控制重新实现 |
| 会话依赖 | 私人界面与 owner 会话绑定 | 历史和笔记在服务故障时仍可用 | 本地访问与远程 AI 权限解耦 |
| 笔记字段 | title/judgment/evidence/invalidation/verification_date 等 | content/invalid_condition/verify_date/revision 等 | 明确字段映射，避免历史判断内容丢失 |
| 备份恢复 | 未找到新版浏览器 JSON 备份恢复实现 | 一键 JSON 导出/导入 | 增加格式版本、冲突提示和恢复验证 |

旧数据库若有用户内容，应先提供显式导出/迁移，再考虑停用旧业务路由。本文不授权删除历史表、数据卷或旧记录。

### 3.2 角色算法的复用边界

- 已有 `trend/core/emotion/catchup/follower/relay` 六个 evaluator，以及独立支持/反证/缺失项和分层能力状态。
- 新 PRD 的 API 枚举为 `emotion_leader/trend_leader/zhongjun/genfeng/buZhang/jieli`，证据状态为 `candidate/insufficient/waiting_verify`；需要显式映射，不能直接把内部枚举透传。
- 现有趋势相对收益使用市场有效成员收益中位数；新版 FAC-R01 和涨幅页要求同窗口市场基准/指数。必须明确角色基准与页面基准的关系，不能把两个指标视为同一口径。
- 当前趋势实现集中在 20/60 日相对收益与回撤；不代表 FAC-R01 的 120 日、FAC-R02 均线斜率、FAC-R03 新高等因子目录已全部覆盖。
- 当前中军规则以成交份额、均额和波动为主；DailyBar 尚无新版要求的流通规模、换手率等完整字段，不能宣称已满足容量证据。
- 六类角色的阈值、排序及 T+5 规则源于旧专项设计。新版 §5.1 是证据框架，未逐项确认这些阈值；可作为候选实现保留，不能自动视为新版已批准公式。
- 旧 Task 7 的算法测试不等于新版梯队页面可用。角色落库/物化/发布/API/UI 在旧计划中属于 Task 8～15，本次源码盘点未发现这些完整链路。

## 4. 数据与 API 差异

| 数据域 | 现有实现 | 新版差异 |
