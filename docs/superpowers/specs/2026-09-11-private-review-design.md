# 第三批：本机私人复盘闭环技术规格

状态：用户于 2026-09-11 批准本文技术规格，并明确进入实施计划与编码。
基线：`9f002b4`；分支：`feature/private-review`；
工作树：工程根目录 `.worktrees/private-review`。

## 一、目标与范围

在第二批只读研究工作台上建立“选快照、加入自选、保存判断、确认复盘、回看验证”的闭环。
对应 PRD 的 REQ-U01～U04 和本机所有者相关 REQ-X01／X02，沿用现有数据许可与快照约束。

本批包括：

- 无账号注册的本机所有者操作上下文、到期与撤销、资源归属和 CSRF 防护。
- 自选加入、移除、撤销移除、幂等重试和稳定证券身份。
- 私人笔记、快照引用、修订历史、并发冲突对照与另存。
- 不依赖 AI 的每日复盘模板、人工编辑和明确确认后的只读版本。
- 原判断与验证期事实并排查看，人工记录支持、削弱、否定或未到期。
- 中文页面与文档、TDD、独立审查、容器及浏览器验收。

不包括真实数据接入、正式题材体系、角色或监管判断、AI、导出、公开分享、
用户注册、远程管理、自动命中率、笔记自动删除、云同步及完整备份恢复产品。
不把本批验收当成完整 P0 发布验收。

## 二、方案与系统边界

沿用 FastAPI、Pydantic、SQLAlchemy、PostgreSQL、React、TypeScript、Caddy，
不新增身份供应商、JWT 服务或数据库。一次性配对与不透明服务端会话比长期浏览器
Bearer Token 更便于撤销；不采用仅凭 Host、回环 IP 或隐藏按钮开放私人接口的方案。

保留 `create_app` 的只读部署契约；新增独立的所有者应用装配入口和私人路由模块。
所有者实例中的行情读取也需有效会话，之后仍执行原来源授权检查。
原只读应用不挂载配对、私人查询和写入路由，未匹配路由默认拒绝。
共享已有快照读模型，不复制金融计算公式，不将整个 `api.py` 改成混合管理入口。

建议模块边界：

- `owner/`：主体、配对、会话、入口与 CSRF 校验。
- `review/`：自选、笔记修订、复盘确认、人工验证契约与服务。
- `storage/`：对应表、事务、并发控制、审计与打包迁移。
- `web/src/features/review/`：私人工作流、编辑器、冲突面板与版本查看。
- 前端行情授权状态、所有者会话状态、未保存草稿状态分别管理。

第三批使用独立 Compose 项目 `dragon-radar-private-review`、数据库卷、凭据文件及
Caddy 证书卷。默认入口 `https://localhost:8030`，宿主端口只绑定 `127.0.0.1`。
API 和数据库无宿主端口；不自动迁移或复制首批、第二批运行实例的数据。
实际端口占用时显式选择新端口，同时更新唯一允许的 Origin 与 Host，禁止自动通配。

## 三、所有者上下文

### 3.1 本机建立

1. 本机 CLI 初始化一个稳定所有者 UUID；重复初始化不生成新身份。
   HTTP 请求不得声明或切换 `owner_id`。多主体仅用于隔离验证，暂不提供账号管理界面。
2. CLI 生成至少 256 位随机一次性配对码，有效期 5 分钟，绑定主体和配置中的精确入口。
   数据库只保存散列、期限与消费状态；生成新码使该主体旧的未使用配对码失效。
3. 配对码写入已忽略的 `.temp/` 文件，写入时即限制当前系统用户和 SYSTEM 访问。
   不输出到日志、URL、命令行参数或前端构建，不自动读取已有用户 `.env`。
4. 用户在已受信任的本机 HTTPS 页面提交配对码。使用 JSON POST、严格 Origin／Host
   和指定自定义请求头，不支持 GET 配对、不启用 CORS、不接受表单编码或查询串凭据。
5. 一次性消费与会话创建在同一事务完成，并发使用同一码最多成功一次。
   无效、已用或过期均返回相同错误。配对失败按安装实例限速，5 次/分钟后返回 429；
   不用 IP 作为所有者身份，数据库错误时关闭配对能力。

仅本机 CLI 可以创建配对码；HTTP 没有初始化主体或签发配对码的端点。
有系统用户或 Docker／数据库管理权限的恶意本机进程不在本应用隔离承诺内。

### 3.2 会话与请求

- 采用至少 256 位随机不透明会话值，数据库仅保存散列；服务端固定 8 小时绝对期限，
  读取不自动续期。CLI 支持撤销该主体的全部会话及待用配对码。
- 会话 Cookie 使用独立名称 `__Host-dragon-private-session`，设置
  `Secure`、`HttpOnly`、`SameSite=Strict`、`Path=/`，不设 Domain。
- 会话创建时生成独立 CSRF 随机值，使用另一个 Secure、SameSite=Strict、Path=/
  且不设 Domain 的 `__Host-dragon-private-csrf` Cookie 提供给前端；
  其散列绑定服务端会话。所有已建立会话的私人变更校验 Cookie、
  `X-CSRF-Token` 与会话绑定值，常量时间比较。CSRF Cookie 不含会话秘密。
- 每个私人读写请求校验会话存在、期限、撤销状态与服务端主体。所有者应用严格校验
  配置 Host；写请求还需精确 Origin 与 JSON 类型。拒绝跨站 Fetch Metadata。
  不信任 Host／Forwarded 推导身份，不用代理头替代会话。
- Caddy 和应用均对路径、方法设置白名单；GET／HEAD 不写笔记、不创建模板或会话。
  私人路径统一 `Cache-Control: no-store`；请求体上限 128 KiB，在解析前限制。
- 私人变更在事务中重新校验会话并与撤销串行化；已提交操作不因稍后撤销而回滚，
  撤销提交后开始的请求不得继续修改。固定锁顺序，避免会话、笔记与幂等锁互相死锁。
- 主体不属于当前会话的资源与不存在资源均返回 404；不返回其他主体内容、版本或存在性。
  无会话、过期或撤销为 401；入口或 CSRF 无效为 403，并返回固定错误代码。
- 显式退出撤销会话并删除两个 Cookie。私人令牌不进入 localStorage、sessionStorage、
  URL、审计明细、异常回显或网络访问日志。

### 3.3 本机 HTTPS

Caddy 为 localhost 使用专属内部 CA；只导出 CA 公钥证书供用户核对，CA 私钥留在
独立受保护卷中。提供显式安装与卸载信任的命令和指纹核对步骤，不静默修改系统信任库。
书面规格批准不替代操作系统证书信任动作的单独确认。

未完成信任前不提交配对码或私人内容，不引导忽略证书警告，也不以 HTTP 回退上线。
浏览器验收使用受信任的测试证书，不以 `ignoreHTTPSErrors` 作为完成证据。
Vite 的生产等价写入联调也需明确 HTTPS Origin，不加入来源通配或默认开发后门。

## 四、私人持久化与并发

使用新增 Alembic 迁移，不修改已发布的首批迁移。主要对象：

| 对象 | 持久化职责 |
| --- | --- |
| `owner_principals` | 稳定 UUID、创建时间；本批一个本机主体 |
| `owner_pairings` / `owner_sessions` | 配对消费、散列、期限、撤销与 CSRF 绑定 |
| `watch_entries` | 主体＋证券唯一、自选状态、来源快照、加入时间、版本 |
| `review_notes` | 主体、记录 ID、类型、当前修订号、原快照引用 |
| `review_note_revisions` | 不可变标题、人工文本、条件、验证日期、版本状态及引用 |
| `review_verifications` | 绑定笔记修订与验证快照的人工结论、依据与记录时间 |
| `owner_commands` | 主体＋幂等键、规范请求摘要、提交结果的资源 ID／版本 |
| `private_audit_events` | 主体、动作、资源 ID／版本、时间与结果，不含正文或凭据 |

外键及唯一约束同时表达资源归属，所有读取和更新条件均包含服务端主体。
笔记修订、验证记录、私人审计禁止 UPDATE／DELETE／TRUNCATE；头指针、自选、
会话状态可事务更新。不在市场数据审计表中伪造 `source_id` 保存私人动作。

私人业务变更请求携带 `Idempotency-Key`；更新、移除、撤销、确认另携带 `If-Match` 版本。
配对使用一次性消费语义，退出使用撤销语义，不进入笔记业务的幂等账本。
未给版本返回 428；版本过期返回 409 和当前主体的服务端版本，禁止静默覆盖。
相同键、方法、路径、规范请求体与预期版本返回原提交结果标识；同键不同请求冲突。
幂等记录、业务修改、修订与审计一次提交，失败整体回滚。重放仍重新校验当前会话及归属，
不把历史响应正文直接当作绕过当前权限的缓存。

保留幂等记录直至显式维护政策另行评审，本批不后台自动清理私人数据。
列表按更新时间和 UUID 稳定分页，默认 50 条，支持 20／50／100。
所有时间使用带时区 UTC 存储，界面明确以北京时间显示。

## 五、自选与笔记

### 5.1 自选

加入时要求快照可读且证券属于该快照预期池，保存稳定证券 ID、快照引用和加入时间。
已在自选中重复加入返回现有条目，不重置加入时间。正式题材尚不存在，题材上下文为空，
不得把自由文本标签冒充正式题材成员；将来可扩展明确来源的上下文。
已移除条目重复 POST 不隐式恢复，返回其当前 ID／版本及冲突提示；
前端经用户确认后使用带版本的状态变更重新加入，禁止绕过并发保护。

移除为软状态变化，返回新版本并提供“撤销”。撤销须匹配移除后的版本；其他会话已修改
时返回冲突，不覆盖后续操作。移除与撤销不要求原行情来源仍有效。
改名时仍按稳定 ID 关联；原快照不可读时保留自选操作与证券 ID，不复用缓存名称或价格。
当前选定快照不存在该证券时显示“本快照无行情”，不自动切换日期或来源。

### 5.2 笔记

记录包含：标题、判断、依据、失效条件、验证日期、绑定快照、可选证券 ID。
标题 1～100 个 Unicode 码点；判断、依据、失效条件合计最多 20000 个码点。
草稿可暂缺判断字段与验证日期；确认版本时三项文本和验证日期必须完整，
验证日期不得早于绑定快照交易日。前后端统一长度与日期语义，拒绝额外字段。

创建时验证快照与证券归属；已有笔记修订沿用原快照，不自动指向新修订版。
更换依据快照使用“另存”形成新笔记。每次保存追加不可变修订，返回保存时间、
修订号与完整回读结果；只有服务端提交成功才显示“已保存”。

并发冲突保留编辑器原文，并排展示原基线、当前输入和服务端最新版。
用户可基于最新版手工合并后再次提交，或另存为新笔记并记录来源修订 ID。
不会自动合并长文本、用客户端时间覆盖服务端版本，或在重试时生成新幂等键造成重复记录。

正文以纯文本编辑和渲染，不执行 HTML、Markdown 内嵌脚本或外部资源。
本批不提供笔记删除入口，不将建议的 30 天保留期直接变成自动清理任务。

## 六、复盘模板、确认与历史验证

“生成每日复盘模板”是经授权的显式 POST，绑定当前选定快照，创建独立草稿。
模板版本固定，包含“市场观察、判断依据、失效条件、待验证事项”等人工编辑区域。
其中市场观察与待验证事项作为判断字段的固定纯文本小节，依据和失效条件沿用笔记字段，
不另设无上限的隐藏正文；所有人工文本仍受同一 20000 码点上限约束。
模板行情事实通过结构化快照引用展示，不自动拷贝价格或原文到人工文本字段。
未接入的角色、监管、消息内容不填充，也不显示默认安全或正常结论。

重新生成始终新建草稿，不覆盖已保存或尚未提交的人工文本。
确认采用预期版本和幂等键：追加确认修订并冻结该记录。确认后不能原地编辑；
“以此新建草稿”创建新记录，保留 `derived_from_revision_id`，旧确认版不变。

历史验证始终针对具体已确认修订。页面左侧展示原判断、条件、验证日期与原快照引用；
右侧展示用户明确选择的验证日期／快照事实及当前授权状态，不自动找相邻日期替代。
本批仅并排查看各自快照已提供的收盘、日涨跌幅与质量字段，不拼接不同快照计算跨期收益。
需要区间研究时沿用现有单快照区间接口的完整日历与数据要求。

是否到期由服务端时钟的北京时间日期与验证日期比较，不使用浏览器时钟。
验证日期未到时只允许记录“未到期”；支持／削弱／否定须由用户明确选择，并填写依据、
指定交易日不早于验证日期的可读验证快照。也显示“尚未验证”作为无记录状态，
不得把事实缺失解释为否定或支持。修正人工结论时追加记录并引用被替代的验证记录。
不自动推导交易建议、策略绩效或命中率；保留回溯快照的事后研究标记。

## 七、授权失效与前端状态

市场来源授权和私人内容访问是两个独立维度。
来源失权后，已保存的用户原创判断、原快照 ID 与证券 ID 仍可由所有者读取和编辑；
快照衍生事实按引用分别显示“来源不可用”，不绕过仓储授权取归档或旧事实缓存。
创建新快照引用、生成模板和新增有事实依据的验证需要当前授权有效。
人工文本不会因来源失权被程序自动删改；也不宣称能识别用户手工粘贴内容的版权属性。

私人响应使用独立错误码和请求处理器，不复用“所有 403 都是行情撤权”的客户端逻辑。
401 时立即锁定并隐藏私人列表、已保存正文和事实，取消在途请求；
当前未保存的用户输入仅暂留页面内存、绑定原主体且不再展示，重新配对同主体后可恢复。
不同主体绝不恢复草稿；显式退出先确认放弃未保存输入并清除内存。
刷新、关闭浏览器或进程崩溃可能失去未提交草稿，本批不承诺离线持久化。

会话、来源、编辑器和行情请求有各自的代次隔离，迟到响应不解除锁定或覆盖输入。
保存超时保留原幂等键，恢复后确认原请求结果再提示成功。
切页、切快照、打开其他笔记、退出和浏览器关闭均覆盖未保存确认；
浏览器关闭使用浏览器原生限制允许的提示，不承诺自定义提示文案。
编辑过程中来源失权、行情刷新或抽屉关闭不得卸载私人草稿状态。

## 八、页面与接口

沿用第二批浅色终端布局、字体、图标和响应式规则。新增“我的复盘”入口，内含
自选、草稿／确认版和历史验证视图。行情列表及详情在有效所有者会话下显示
自选和记录笔记动作；未配对时不加载私人资源。页面无假数据或占位业务结论。

私人正文、配对码、会话、幂等键不进入查询串。页面 URL 仅保留视图、记录 UUID、
快照 UUID 与公开筛选条件，服务端不因知道 UUID 就允许读取。
保存、冲突、锁定、离开确认与撤销使用原生可访问控件，键盘和手机均可操作。

拟定路由（所有者应用专有，精确方法白名单）：

| 路径 | 方法与行为 |
| --- | --- |
| `/api/owner/v1/pair` | POST 一次性兑换会话 |
| `/api/owner/v1/session` | GET 状态；DELETE 退出 |
| `/api/owner/v1/watchlist` | GET 分页；POST 幂等加入 |
| `/api/owner/v1/watchlist/{id}` | PATCH 带版本设置加入／移除状态 |
| `/api/owner/v1/notes` | GET 分页筛选；POST 新建草稿 |
| `/api/owner/v1/notes/{id}` | GET 当前版本；PATCH 保存草稿新修订 |
| `/api/owner/v1/notes/{id}/revisions` | GET 自有修订列表 |
| `/api/owner/v1/notes/{id}/revisions/{version}` | GET 自有具体修订 |
| `/api/owner/v1/notes/{id}/confirm` | POST 带版本确认 |
| `/api/owner/v1/notes/{id}/fork` | POST 从指定修订另存新草稿 |
| `/api/owner/v1/review-templates` | POST 为指定快照新建确定性模板草稿 |
| `/api/owner/v1/notes/{id}/verifications` | GET 历史；POST 追加人工验证 |

私人记录响应不伪装成行情快照封装，分别提供资源版本、服务器保存时间、
主体范围内引用及按当前许可解析的事实。400／422 参数错误，401 会话无效，
403 入口或 CSRF 拒绝，404 资源不可见，409 冲突，428 缺版本，429 限速，
503 存储不可用；错误不回显正文、凭据、SQL 或连接串。

## 九、验收与实施顺序

按“所有者入口、私人存储与服务、复盘界面、容器及回归”顺序实施，
每项先失败用例、后最小实现，再做规格复核与质量审查。
所有权与接口契约未稳定前不并行编写互相依赖的实现文件。

验收至少包括：
